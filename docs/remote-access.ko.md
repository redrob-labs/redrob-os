# 원격 접속

폰(또는 아무 클라이언트)이 레드롭 OS 기기의 대시보드와 에이전트에 닿는 방법.

경로는 둘. 클라이언트가 어디 있느냐로 고른다.

| 클라이언트 위치 | 경로 | 서버 필요? |
|---|---|---|
| 기기와 같은 Wi‑Fi/LAN | **LAN 직접** | 아니오 |
| 그 밖(모바일 데이터, 다른 망) | **릴레이** | 예 — 직접 운영하는 릴레이 |

## LAN 직접 (기본, 같은 망)

기기 게이트웨이(대시보드+페어링)가 `:42617`에서 모든 인터페이스로 듣는다.
모든 경로는 일회용 **페어링 토큰**으로 막혀 있어, 페어링된 클라이언트만 들어온다.

1. 폰을 기기와 **같은 Wi‑Fi**에 둔다.
2. 기기 화면의 페어링 QR을 찍는다(또는 시리얼로 코드 확인).
   QR 내용: `redrob://pair?device=<id>&host=<기기-ip>:42617&code=<code>&fp=<sha256>`.
3. 폰이 그 코드로 페어링하고 `https://<기기-ip>:42617` 대시보드를 연다.
   이때 SHA‑256 지문이 `fp`인 인증서만 신뢰한다(핀 고정).

암호화: 리스너는 **HTTPS**다. 에이전트가 첫 시작 때 데이터 폴더(`gateway-tls/`)에
인증서를 스스로 만들고 이후 계속 재사용하므로 재부팅해도 핀이 유지된다. 자체 서명
인증서라 클라이언트는 `fp`로 고정해야 하고, 브라우저로 직접 열면 인증서 경고가 뜬다.
루프백 호출(헬스 체크, 페어링 배너)은 같은 포트에서 평문 HTTP도 쓸 수 있다.
평문만 쓰려면 `[gateway.tls] enabled = false`(신뢰된 LAN에서만).

## 릴레이 (어디서든)

LAN 밖에선 폰이 기기의 사설 주소에 못 닿는다. **릴레이**는 기기가 바깥으로
다이얼아웃하는 공개 랑데부 지점이고, 폰은 불투명한 node id로 릴레이를 *거쳐*
기기에 닿는다. 릴레이는 **깜깜이 전달자**다 — 클라이언트↔기기 mTLS는 기기에서
끝나고 릴레이에선 절대 안 풀린다. 그래서 릴레이는 평문 트래픽을 못 본다.

Redrob는 아직 공개 릴레이를 운영하지 않으므로, 자기 릴레이를 띄운다. 공개 주소가
있는 호스트에 바이너리 하나(`zerorelay`)면 된다.

### 1. 공개 호스트에 릴레이 띄우기

```sh
# 공개 IP나 DNS 이름이 있는 VPS/박스에서:
zerorelay \
  --bind 0.0.0.0:8443 \
  --tls-san relay.example.com \      # 릴레이의 공개 호스트명
  --relay-token "$(head -c24 /dev/urandom | base64)"   # admission 토큰; 보관
```

- `--tls-cert`/`--tls-key` 없음: 릴레이가 첫 실행에 TLS 인증서를 **자가 발급**
  하고(openssl 불필요) 이후 재사용한다.
- 출력/수용되는 `--relay-token`이 기기가 제시해야 할 admission 자격이다. 저장해 둔다.
- 호스트 방화벽/보안그룹에서 인바운드 TCP `8443`을 연다.

### 2. 기기를 릴레이로 가리키기

기기 대시보드에서 **Network → Relay**를 열고 설정:

| 항목 | 값 |
|---|---|
| `enabled` | `true` |
| `url` | `relay.example.com:8443` |
| `token` | 1단계의 `--relay-token` (암호화 저장) |
| `tofu` | `true` — 릴레이 자가 발급 인증서를 첫 접속에 신뢰 |
| `node_id` | 비워 둠 — 기기가 랜덤 id를 자동 발급·보존 |

(설정 파일을 직접 고치면 `agent.toml`의 `[relay]` 키와 동일.)

`node_id`는 비워 둔다: 자동 발급 랜덤 id는 추측 불가라, 모르는 사람이 릴레이를
통해 기기를 쑤셔보는 것을 막는다. 그러면 기기가 릴레이로 상시 아웃바운드 연결을
유지하고, 어디서든 node id로 닿을 수 있다.

### 보안 메모

- `tofu = true`는 처음 본 릴레이 인증서를 신뢰한다. 더 강하게 핀하려면
  `relay_ca_path`에 릴레이 CA를 넣는다. `relay_insecure = true`는 로컬 테스트
  외에는 쓰지 않는다.
- admission `token`은 릴레이 *등록*만 막는다. 대시보드/에이전트의 모든 경로는
  릴레이 여부와 무관하게 여전히 에이전트 **페어링 토큰**이 막는다.
- 릴레이는 암호문과 node id 트래픽 메타데이터만 보고, 요청 내용은 못 본다.
